Knuth-Bendix Completion

Enter equations lhs = rhs, one per line. Identifiers starting with u v w x y z are variables; everything else is a function symbol or constant. # starts a line comment.

About these algorithms — orderings, limitations, syntax

Knuth-Bendix completion turns a set of equations into a confluent rewrite system: every term reduces to a unique normal form, so equality in the equational theory becomes a syntactic check. This page runs two implementations entirely in your browser (Python via Pyodide).

What each algorithm does

  • Standard Knuth-Bendix treats every function symbol as uninterpreted. It uses Huet-style completion: orient each equation into a rule, simplify existing rules with the new one (compose / collapse), then add every critical pair (overlap between rule LHSs) as a fresh equation.
  • AC Knuth-Bendix lets you declare function symbols as associative and commutative — e.g. addition, multiplication, set union. AC subterms are flattened and canonically sorted (so p(a, b, c) and p(c, p(a, b)) have identical Python representations). Rewriting uses AC matching (a variable under an AC head may absorb a multiset of arguments); critical pairs use AC unification; and for every AC-rooted rule an extension rule f(l, X) → f(r, X) is added so overlaps at non-root positions aren’t missed.

Orderings (termination proofs)

Both algorithms orient equations using a recursive path ordering (RPO) parameterised by a precedence on function symbols.

  • Standard mode — LPO (lexicographic status for every symbol). s = f(s₁,…,sₘ) ≻ t if any of:
    • some sᵢ = t or sᵢ ≻ t; or
    • f outranks the head of t, and s ≻ tⱼ for every argument of t; or
    • heads are equal and the argument tuples are lex-greater (with s ≻ tⱼ for the remaining arguments).
  • AC mode — RPO with multiset status under AC heads. Same scheme, but when the two heads are equal and the head is AC, comparison reduces to multiset comparison of the (flattened) argument lists. This is required because f(a, b) and f(b, a) must be ordered the same way.

Precedence is supplied as a comma-separated list, highest first (e.g. i, m, e means i > m > e). Any symbol you don’t list gets rank 0 and is considered equal to all other unlisted symbols.

Limitations

  • Completion is semi-decidable. If a finite confluent system exists and the precedence orients every generated equation, the procedure will find it. If not, it can fail with “cannot orient” or simply never saturate. Hitting the iteration limit does not prove no finite system exists — a different precedence may succeed.
  • Orientation must always succeed. RPO is silent on equations like commutativity f(x, y) = f(y, x) where both sides have the same head and identical multisets of variables. Such equations can only be handled by declaring f as AC and switching to AC mode.
  • AC unification here is enumerative and assumes every variable binds to a non-empty term — empty bindings (a unit element being absorbed into an AC operator) are not supported. Don’t expect Boolean rings or anything that needs to identify f(x, e) with x via the unifier.
  • No conditional rules, no built-in equality predicate, no sorts. Identifiers are just strings; there’s no type or arity checking.
  • Performance. AC unification is exponential in the worst case. Realistic AC examples can blow up quickly; the iteration limit is the only brake.

Syntax cheatsheet

  • One equation per line: lhs = rhs
  • Function application: f(g(x), y, c). Constants are nullary applications written without parens (c, e, 0).
  • Variables: identifiers starting with u v w x y z — so xs, y1, zoo are variables; a, b, e, f1 are constants/functions.
  • Comments: # to end of line.
  • AC operators: comma-separated symbol list (e.g. p, plus).
  • Precedence: comma-separated, highest first.

What to do when it fails

MessageMeaningWhat to try
Cannot orient: s = t RPO can’t decide which side is bigger under the current precedence. Reorder the precedence so the head symbol of the side you want as the LHS comes earlier. If both heads are equal and the argument multisets coincide (e.g. commutativity), the equation is genuinely unorientable — declare the head AC and switch to AC mode.
did not saturate in N iterations Critical pairs kept being generated past the iteration budget. Raise “Max iterations”. If it still doesn’t finish, try a different precedence; the theory may have no finite confluent presentation under any ordering this implementation supports.
parse error / missing = The input couldn’t be parsed as lhs = rhs. Each non-blank line must contain exactly one =; check parens balance and that variable letters match the convention above.
recursion-limit error A generated term grew large enough to blow Python’s stack. Lower the iteration limit or simplify the precedence; usually a sign the system is diverging.
